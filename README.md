# 去趣 TripMate｜排行程 RPG Prototype（v8）

SETUP（人格快測 → 預算／網路 → 建房或加入，房主可設地點、日期、天數）
→ GAME（視覺小說式 4 站答題 + 大提示）→ SUMMARY（人格結算 + 雙欄常駐 eSIM 導購）
→ PLAN（AI 滑卡推薦 + 後台交通計算 + 共享行程看板）。
全部邏輯與畫面都在單一檔案 `src/App.jsx`。

```bash
npm install
npm run dev
```

## 真實資料：`data-pipeline/`

規格書模組四原本用亂數產生的大阪景點資料，改由 `data-pipeline/` 實際抓取：
Google Maps（官方 Places API）＋ PTT Japan_Travel（爬蟲）＋ Threads（官方 API，選用）＋ Dcard／小紅書（人工收集表），
整合成同樣 16 個欄位的 `osaka_travel_dataset.csv`，每筆都附來源網址。步驟見 [`data-pipeline/README.md`](data-pipeline/README.md)。

## v8 新增：答題改成視覺小說 + 人格角色造型

**答題畫面（`VNStage`，取代原本的 `RoundCard`）**：

- 每站一張場景背景（`SceneBackdrop`，純 SVG）：飯店晨窗（窗外下雪）、樂園入口（人潮都在滑手機）、
  道頓堀雨夜（霓虹會閃、運河有倒影）、心齋橋商店街（「營業至 20:30」吊牌）
- 隊友用人格角色站在場景裡；誰在講話誰往前站、其他人變暗；點角色可以看他是哪一型人格與招牌動作
- 劇情節奏：旁白（`ROUNDS.scene`）→ 趣趣發問（`ROUNDS.line`）→ 1～2 位隊友搭話（`CHATTER`）→ 選項浮出
- 對話框有名牌與頭像，點畫面或按 Enter 推進；LOG（對話紀錄）／AUTO（自動播）／SKIP（直接跳到選項）
- 選了答案，你的台詞會出現在對話框，按「就這麼辦」才送出；選項邏輯、計分、網路卡頓事件都沒變
- 站點、默契值、大地圖收進舞台上方的 HUD

**人格角色造型（`PERSONA_IP` + `GEAR` + `PersonaFace`）**：照 `chictripPersonas.ts` 的規格，
在原本的趣趣行李箱身體上換眼型（eyeShape）、配件（accessory）、點綴色（accentColor）。
人格判定邏輯完全沒動。對照如下（計程車星人在那份沒有，用同一套規則補上；味蕾老饕這個專案沒有對應人格）：

| 行程特種兵 | speed_runner | 超響亮擊掌 | 急速滑步離場 |
| 隨性慢活水豚 | chill_capybara | 一起吐放空泡泡 | 化成一灘黃水 |

## v7.7 修正：購買前確認條款 + 購買後的去向

**條款移到購買前，而且要勾選才能買**：原本「購買前要知道的幾件事」是摺疊的、放在購買按鈕下方，

**購買後講清楚買到什麼、對應哪一版行程、接下來怎麼辦**：

**已購買後行程被改動，再打開面板會警告**：

  （新增 4 個地點）。建議回行程頁重新定版後，在這裡加購或換更大的方案。」
- 用量沒超過的話則顯示「行程改過了，你買的方案還夠用」

## v7.6 新增：行程定版

**要解決的問題**：買完 eSIM 之後行程還在變，導致「最後行程到底是哪一版」和
「買的方案還夠不夠用」永遠沒有答案。

**做法**：導出與方案推薦之前，先要求「定版」。

| 狀態 | 行程 | 可以做什麼 |
| --- | --- | --- |
| 未定版 | 可自由編輯 | 只有「定版這份行程」 |
| 已定版 | **唯讀**（拖曳握把、▲▼、刪除鍵全部隱藏） | 導出圖片、看網路方案、解除定版 |
| 已定版＋已購買 | 唯讀，卡片顯示已買的方案與電信商 | 同上；解除定版會先跳確認 |
| 解除後編輯中 | 可編輯 | 顯示「和上一版的差異」，可重新定版 |

- 定版時快照當下的行程、用量估算與地點數（`lockPlan`），方案面板標明「依 X 月 X 日 XX:XX 定版的行程計算」
- 解除定版後改行程，會即時比對差異（`comparePlan`）：新增／刪除了哪些地點、用量從幾 GB 變成幾 GB
- **已購買後解除定版會先確認**，並提醒 eSIM 售出後不接受個人因素退換貨
- 若改完後用量超過已購方案的每日流量，差異卡會跳紅字警告建議加購（吃到飽不會觸發）
- 購買記錄存在定版快照裡（`recordPurchase`），重新開啟方案面板會回填已選的方案與電信商

## v7.5 修正（依方案整理文件重做）

**折扣改成 85 折**：去趣官網常態全館 85 折，原本設定的「團購 9 折」反而比官網差。
現在 `SITE_DISCOUNT = 0.85`，且敘事改成「全館 85 折已自動帶入」而不是謊稱團購專屬。
驗證：26×0.85＝22、95×0.85＝81，與官方標價完全吻合。

**一起買的價值改成講實話**：折扣本來就有，所以「一人一張」的理由改成——
熱點分享會受手機系統限制（SoftBank 方案的 Android 無法開熱點），而且一分流就有人沒網路。

| 方案 | 原價／日 | 85 折 | 來源 |
| --- | --- | --- | --- |
| 🌱 每日 500MB | NT$26 | **NT$22** | 官方標價 |
| 🍃 每日 1GB | NT$35 | NT$30 | 推估 |
| 📶 每日 2GB | NT$48 | NT$41 | 推估 |
| ⚡ 吃到飽不降速 | NT$95 | **NT$81** | 官方標價 |

**電信商改成依行程推薦**（去趣「可挑線路」的價值所在）：

| 行程分布 | 推薦 | 理由 |
| --- | --- | --- |
| 全部在市區商圈 | SoftBank（原生・5G） | 都市基地台密度最高，拍照上傳最順 |
| 市區為主＋1 個郊區 | 不限電信商（漫遊・5G） | 自動切換當地最強訊號 |
| 郊區 ≥2 個且占比 ≥25% | Docomo(IIJ)（原生・4G） | 郊區涵蓋四家最高 |

各家的限制也直接寫在畫面上：SoftBank 的 Android 不能開熱點、漫遊線路會慢 1–2 秒、
Docomo 市區偶爾卡頓且為 4G。

**購買前注意事項**照文件補齊：恕不接受個人因素退改、憑證兌換期限 180 天、
下單 20 分鐘內發券、24 小時 LINE 中文客服、KDDI 吃到飽熱點上限為購買天數減 1GB。

## v7.1 修正

- **方案選不了**：原本每個人只列「比團購方案更高階」的選項，所以 AI 推薦最高階（電競版）時整排只剩「跟團購一樣」一顆按鈕；想選更省方案的人也無從選起。改成**三個方案一律列出、都可挑**，團購推薦的那個標綠底徽章。
- **價格規則簡化**：改為**每個方案各自享團購 9 折**（輕量 63／吃到飽 90／電競 144），選貴的自己加價、選便宜的自己省下，比原本「升級差額照原價」好懂也公平。
- **用量估算重算**：原本把分流加成也除以天數，導致天數越少每日用量估得越高（3 天行程會被推到電競版）。改成隨景點數的項目取每日平均、分流加成固定不稀釋。現在 3／5／7 天的同密度行程都落在 2.3–2.4GB。
- **電競版不再由行程推薦**：手遊、直播是個人習慣，行程推不出來，所以團購推薦只在輕量／吃到飽之間選，電競版留給個人加價。
- **隊友預設放開**：Mock 隊友依人格各自挑（特種兵→電競版、水豚和精算師→輕量），畫面上直接看得到「每個人需求不一樣」。

## v7 新增（循序漸進的導購節奏）

導購拆成三段，不在行程還沒定時就推方案：

| 階段 | 做什麼 | 實作位置 |
| --- | --- | --- |
| ① 快測完成 | 解鎖全隊團購優惠碼（只說「一起買有 9 折」，不推方案） | `couponCode()` + `SetupScreen` Step 1 優惠碼卡 |

| ③ 行程排完 | 導出行程圖片 → 依實際行程算用量 → 推薦方案 | `renderItineraryImage()` → `ExportSheet` → `NetworkPlanSheet` |

其他：

| 需求 | 實作位置 |
| --- | --- |
| 行程導出成圖片存手機 | `renderItineraryImage()`（純 Canvas 繪製，1080px 寬，含優惠碼；無 canvas 環境回傳 null 並提示改用截圖） |

| 時段已滿時可直接取代 AI 預排 | `arrangePicks()` 新增 `action: "swap"` + `replaces` |

## 換成真後端

- 交通時間：`travelMinutes` → Google Directions / 交通 API（回傳分鐘數即可）
- 景點資料：`POIS` → Places API 或自家 POI DB（需 lat/lng、建議停留時間、標籤）
- 編排邏輯：`arrangePicks` / `suggestSlot` / `bestOrder` → 後端排程服務或 LLM，介面不用改
- 同步：`board`、`feed` → WebSocket（board 是單一真實來源）
